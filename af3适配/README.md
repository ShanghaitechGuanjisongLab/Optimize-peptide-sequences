af3适配 — AF3 任务的任务中间层适配层
=====================================

本目录是 **AF3 专属**的任务适配逻辑（放在 AF3 自己的项目里，通用调度工具 `../../任务中间层/` 不含任何任务适配）。

# 组成

```
af3适配/
├── msa缓存.py   # AF3 MSA 磁盘缓存: 提取/内嵌/自愈收割
└── af3任务.py   # AF3 JSON → 任务中间层任务（生成启动器+提交+等待）
```

# MSA 磁盘缓存（msa缓存.py）

单任务粒度的最大障碍是 MSA 摊销失效（靶标链搜索 ≈78min/进程）。解法：
**内嵌 MSA** —— AF3 输入 JSON 的每条链可带 `unpairedMsa`/`pairedMsa`/
`templates` 三件套，三件齐全时 data pipeline **完全跳过搜索**。缓存值全部取自 AF3 自己输出的 `_data.json`（pipeline 的真实搜索结果），回放即特征逐字节等价 —— 前提是数据库与 max_template_date 配置不变（本项目一直如此）。

- 靶标链（恒定序列）：播种自历史结果，永久免搜索；
- 肽链：首次任务现场搜索，完成时自动收割入缓存（自愈），同序列后续任务复用。

缓存根：`peptide_opt_db/msa_cache/`（可用 `PEPOPT_MSA_CACHE` 覆盖）。

# 任务流（af3任务.py）

`小肽优化_节点内.run_af3_cycle` 默认走此路径（`PEPOPT_HQ_MODE=0` 可强制回退整包直跑）：每个 AF3 JSON 一个独立任务（一任务一 job → `任务控制.sh cancel <id>` 精确取消单个预测），生成的启动器在任务开始时内嵌缓存 MSA、结束时收割本任务的 MSA 入缓存（同序列后续任务自动免搜索）。

手动补算/试算：`任务中间层/任务控制.sh add --name seqX_htr1a --gpus 1
--gpu-memory 10 --priority 10 -- bash……`（priority 越大越先跑）。

# 显存需求估算

AF3 提交时根据输入 JSON 的蛋白复合物大小声明显存，**不按 32/40/80 GB
显卡容量取档**。肽链和靶标的全部同源拷贝都计入 token；随后按当前 runner
默认的 AF3 编译 bucket 补齐。超过最大 bucket 5120 时按实际 token 数处理。

当前估算为 `ceil((固定开销 + pair系数 * (bucket / 1024)^2) * 余量)`，单位 GiB：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `AF3_MEMORY_FIXED_GB` | 6 | 权重及固定运行开销的估算 |
| `AF3_MEMORY_PAIR_GB` | 8 | 每 1024-token 平方项的估算系数 |
| `AF3_MEMORY_MARGIN` | 1.15 | 容量余量，必须至少为 1 |

这是一套**尚未由峰值实测标定的初始容量模型**，不是 AF3 官方显存公式。
默认针对当前 bfloat16、5 个扩散样本和默认 bucket 配置；attention 实现、
MSA 深度、分片和统一内存都会影响实际峰值，变更配置后应据实测调整系数。
目前仅支持项目使用的纯蛋白体系；遇到配体或核酸会拒绝估算，不能静默忽略。

19 aa 原肽对应的默认声明为：HTR1A（441 tokens / bucket 512）10 GiB，
BIN1（612 / 768）13 GiB，ASIC1A 三聚体（1597 / 2048）44 GiB，
UNC13C（约 2233 / 2560）65 GiB。改变序列或拷贝数会重新计算，而改变
可用显卡型号不会改变任务声明。HQ 只负责匹配容量足够的卡，扩容时仍优先大卡。
